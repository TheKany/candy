# 회원 관리 구현 기록

계획: `superpowers/plans/2026-09-28-member-admin.md`

- 회원 목록/검색/일반·슈퍼 변경 확인/결제 상세 빈 상태 구현.
- 제한된 DB RPC에서 관리자 권한을 재검증. 기존 본인 전용 RLS 유지.
- 난수 회원번호, 역할 변경 이력, 버전 기반 슈퍼 안내 확인 마이그레이션 작성.
- 마이페이지 진입 시 계정 재조회, DB 확인 성공 후 안내 숨김. 확인 버튼은 “확인했어요”.
- 실제 결제 연동은 아직 하지 않음. 2026-09-28 사용자 확인 후 운영 DB 마이그레이션 및 유일한 기존 회원의 관리자 지정을 완료했다. 배포 진행 중.

## 검증 및 적용 메모

- `tests/adminInput.test.ts`: 입력 검증 3건 통과. 모듈 구현 전 실패 확인 후 통과.
- `supabase/tests/member_admin.sql`: 2026-09-28 승인 후 롤백 트랜잭션 검증 통과. 일반/슈퍼 관리자 접근 차단, 직접 관리자 자기 지정 차단, 등급 버전·확인 초기화·오래된 확인 거부·90일 상태 경계·회원번호 중복 방지 확인. 결과 checks_passed, 잔여 테스트 사용자 0.
- 최초 관리자 UUID는 본인 확인 후 `member_admins`에 지정해야 한다. 슈퍼 등급이나 이메일만으로 자동 부여하지 않는다.
- 운영 마이그레이션과 해당 API/클라이언트 배포는 함께 수행해야 한다. 무인자 확인 RPC가 버전 인자 RPC로 바뀌므로 예전 클라이언트는 새로고침이 필요할 수 있다.
- DB 적용 전 일반 로그인은 유지한다. 신규 role_version 열이 없으면 관리자 권한은 false, roleVersion은 null이며 신규 슈퍼 안내는 표시하지 않는다.

## 판단 사항

- 사용자 요청대로 현재 브랜치에서 직접 작업하고 병렬 에이전트/추가 테스트 도구/전체 테스트를 사용하지 않음.
- 운영 DB 검증 완료. 기존 실제 회원의 상담 내용과 등급은 변경하지 않고 별도 관리자 권한만 부여했다. 실제 가입자 1명, 관리자 1명 확인.
- 결제 이력을 임의 생성하지 않고 paymentsConnected=false로 제공. 결제 연동 이후 실제 원장 연결이 필요함.
