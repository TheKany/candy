# 월별 타로 구현 기준

## 목적과 확정한 흐름

특정 질문을 받지 않고 올해 남은 달의 흐름을 살펴보는 리딩이다. 타로 선택 → 카드 섞기 → 달마다 한 장 선택 → 월별 카드 목록 → 해당 월 상세 순서로 진행한다. 기존 한 장·세 장·다섯 장 상담은 그대로 유지한다.

- 한국 시간 기준 이번 달부터 같은 해 12월까지, 최대 12장이다. 9월에는 9~12월 4장을 뽑는다.
- 시작한 연도와 월은 세션 동안 고정한다. 월말에 페이지를 넘겨도 선택 개수나 월 배정이 바뀌지 않는다.
- 한 덱에서 중복 없이 정방향으로 뽑는다. 기존 섞기·훑기·숫자 입력·결정·뒤집기 동작을 재사용한다.
- 카드 자리에는 `9월`, `10월`처럼 월을 표시한다. 다음에 뽑을 월도 안내한다.

## 결과 화면

### 전체 보기

월, 카드 이미지, 카드 이름, 해설에 어울리는 짧은 별명을 표시한다. 카드를 누르면 해당 월 상세로 이동한다. 280px에서도 글자가 겹치지 않는 반응형 카드 목록으로 구성한다.

### 월별 상세

1. 해당 월, 뽑은 카드, 별명, 짧고 명확한 핵심 메시지.
2. 금전 / 일·학업 / 인간관계 / 마음·생활 해설. 각 항목은 카드의 의미를 일상에서 살펴볼 행동과 연결하는 2~3문장으로 쓴다. 월 상세 안에서는 세로 스크롤을 허용한다.
3. 회색 네잎클로버에 0~100 지수만큼 초록색을 채운다. 숫자와 함께 짧은 설명을 제공한다. 실제 성공 확률이나 통계가 아니라 재미로 보는 카드 흐름 지표임을 작게 안내한다.

하단의 이전 달 / 전체 보기 / 다음 달 버튼은 항상 찾기 쉬운 고정 영역에 둔다. 본문에 하단 여백을 확보한다. 첫 달과 마지막 달에서는 없는 방향을 비활성화한다. 화면을 스와이프하거나 본문을 눌러 월이 넘어가지는 않는다.

## 해설과 데이터

- 선택 완료 후 월과 카드 전체를 Gemini에 한 번 요청한다. 월을 이동할 때는 다시 요청하지 않는다.
- 기존 DB의 카드 프로필과 편집된 카드별 핵심 의미를 근거로 사용한다. 월별 전용 프롬프트와 JSON 검증을 추가해 기존 상담 프롬프트를 변경하지 않는다.
- 반환값은 월별 카드 식별자, 별명, 핵심 메시지, 네 가지 해설, 행운 지수와 설명이다. 서버가 카드와 월의 개수·순서·중복·지수 범위를 검증한다.
- 월별 문장을 서로 복사하지 않도록 하고, 없는 사건·타인의 속마음·투자 수익·취업/합격을 확정하지 않는다. 점수가 낮아도 불안을 부추기지 않고 준비할 행동을 설명한다.
- 최대 12개월 응답을 고려해 월별 전용 출력 한도를 사용한다. 시간 초과·한도·연결 문제에는 기존 로딩/오류 화면을 연결하고, 뽑은 카드는 유지한다. 일반 월 이동은 추가 호출하지 않지만 오류 재시도는 추가 요청이다.
- 선택과 결과는 해당 브라우저 세션 메모리에 보관한다. 새 DB 테이블, 로그인, 결제, 서버 상담 기록 저장은 추가하지 않는다. 새로고침으로 선택 정보가 사라지면 타로 선택으로 안내한다.

## 코드 연결 범위

- `monthly` 리딩 유형을 추가하고 질문 페이지를 건너뛰어 카드 선택으로 연결한다.
- 월별 세션의 연도/시작 월/결과를 관리하고 리셋 시 함께 비운다.
- 기존 카드 선택의 필요 장수, 월별 자리 배치, 선택 완료 판정을 확장한다. 기존 개인 질문이나 연계 상담 데이터가 월별 리딩에 섞이지 않게 한다.
- 월별 해설 API와 결과 컴포넌트는 분리하되 Gemini 호출과 오류 표시 코드는 재사용한다.
- 월별 결과의 종료는 홈으로 이동한다. 기존 질문형 상담의 추가 질문 기능은 변경하지 않는다.

## 필요한 확인만 수행

1월 12장·9월 4장·12월 1장 산정, 중복 선택 방지, 월/카드 대응과 응답 검증을 확인한다. 280px에서 카드 선택과 결과 이동, 클로버 채움과 고정 버튼을 확인한다. 브라우저 흐름 검사는 가짜 해설로 수행해 API 사용량을 소모하지 않는다. 배포 전 빌드를 확인한다.
