# 타로타르트 회원 기능 설계

## 목적과 현재 상태

회원·비회원·지인용 슈퍼 회원을 구분하고 카카오 로그인, 회원의 직접 상담 저장을 제공한다. 향후 타르트 시트 구매와 광고 보상을 계정 기준으로 연결한다. 모바일 최소 280px, 기존 디자인과 결과 흐름을 유지한다.

2026-09-27 확인: 카카오 앱 1283085(타로타르트)의 로그인은 설정되지 않았고, 기존 Supabase 프로젝트의 Kakao 제공자도 비활성이다. 이메일 없이 로그인하는 옵션이 제공된다. 기존 코드에는 회원 인증·시트 결제·실제 보상형 광고 연동이 없다. 상담 임시 기록·묶음 내려받기 변경은 작업 폴더에 있으며 보존한다. 집계 수정은 이번 범위에서 제외한다.

## 접근 방식과 단계

권장: 기존 Supabase Auth의 Kakao 제공자 + Next.js 서버 인증 + DB 행 단위 접근 제어(RLS). 자체 OAuth·세션 서버는 구현 및 보안 관리 범위가 커지므로 사용하지 않는다. 별도 회원 인증 서비스도 추가하지 않는다.

1차는 로그인, 홈 진입, 회원의 직접 기록 저장·조회·삭제, 슈퍼 권한과 첫 안내까지 구현한다. 2차는 결제·시트 원장·광고 보상과 이용권 검증이다. 2차에서 비회원 주문 복구, 시트 유효기간, 승인된 결제 및 광고 제공자를 확정한다. 결제·광고 미연동 상태에서 가짜 구매 성공이나 광고 보상은 제공하지 않는다. 1차를 공개한다고 전체 유료 전환이 완료된 것으로 안내하지 않는다. 실제 과금 전환은 2차 준비 완료 후 명시적으로 진행한다.

## 승인된 이용 정책

- 회원: 유료 상담, 타르트 시트 구매 및 보유, 하루 광고 3회 완료 시 무료 시트 1장, 직접 선택한 상담만 계정 저장.
- 비회원: 무료 광고 보상 없음. 상담·추가 질문 모두 구매 대상. 계정 기록 저장 불가, PDF·이미지 내려받기는 유지.
- 슈퍼 회원: 각자 카카오 로그인한 뒤 지정된 계정에 무료 권한 부여. 모든 타로·연계 질문 무료, 광고 불필요, 계정에 질문·해설 저장 불가. 관리자 권한은 없음.
- 타르트 시트 1장 = 추가 질문 1회. 구매분·무료분 모두 서버의 계정 잔액으로 관리하며 브라우저 캐시 삭제와 무관하게 복구한다.

## 로그인과 홈 화면

- 비로그인: '회원으로 이용하기', '비회원으로 이용하기'.
- 비회원 선택 시 회원 혜택 팝업: 시트 미리 구매, 매일 광고 3회로 무료 시트, 내 타로 기록 저장·다시 보기. 하단 '그냥 이용할래요', '회원으로 이용할래요'. 미연동 기능을 이미 이용 가능한 것으로 오인시키지 않도록 제공 상태를 구분한다.
- 로그인 상태: 재선택 없이 시작하기와 내 계정/내 기록, 로그아웃 제공. 로그인 확인 중에는 비회원 버튼이나 잘못된 권한을 잠깐 표시하지 않는다.
- Supabase Auth 세션을 유지하고 만료 시 SDK로 갱신한다. 캐시 삭제 후 같은 카카오 계정으로 로그인하면 같은 사용자 ID로 복구한다. 권한 판정은 서버에서 검증한 사용자 ID를 사용한다.
- 카카오 OAuth는 PKCE를 사용하는 Supabase의 Next.js SSR 경로로 연결한다. 운영 및 localhost 콜백만 명시적으로 허용하고 외부 URL로 임의 리다이렉트하지 않는다. 카카오 Client Secret은 Supabase 인증 설정에만 등록하고 클라이언트 번들에 넣지 않는다.
- 현재 비즈 앱이 아니므로 이메일을 필수로 요구하지 않고 Supabase의 'Allow users without an email'을 사용한다. 필요한 최소 동의항목만 요청하며 앱 DB에 카카오 프로필·이메일을 별도로 복제하지 않는다. 인증 서비스에 보관되는 식별 정보는 개인정보 안내에 반영한다.

## 최소 데이터와 권한

- member_accounts: auth.users ID, account_role(member/super), super_notice_ack_at, 생성 시각. 역할 변경은 운영자만 서버/DB에서 수행한다. 사용자가 자기 프로필을 수정해 super로 승격할 수 없어야 한다.
- saved_consultations: ID, 소유자 ID, 상담 묶음 ID, 버전, 상담 내용 JSON, 생성·갱신 시각. 동일 상담 저장 재시도는 한 기록으로 처리하고 연계 질문 추가 후 다시 저장하면 해당 묶음을 갱신한다.
- 사용자는 자신의 계정 및 저장 기록만 읽는다. 기록 저장/수정은 서버에서도 회원 권한을 확인하고 DB에서도 소유자와 member 역할을 검증한다. 비회원과 super는 직접 DB API를 호출해도 저장할 수 없다.
- super의 안내 확인은 자기 계정의 확인 시각만 갱신하는 제한된 서버 작업으로 처리한다. 역할 필드는 절대 클라이언트에서 변경하지 못한다.
- 서비스 키가 필요한 운영 작업은 서버 전용이며 환경변수/키를 화면·로그에 출력하지 않는다. 비밀키를 문서나 저장소에 기록하지 않는다.

## 상담 기록과 개인 정보

- 자동 저장하지 않는다. 회원에게만 '내 기록에 저장' 제공. 질문·뽑은 카드·해설을 처음 질문부터 각 연계 질문 순으로 묶는다. 저장 요청 전까지는 기존 메모리 기록만 사용한다.
- '내 타로 기록'에서 본인 기록의 다시 보기, PDF·이미지 내려받기, 삭제를 제공한다. 삭제는 확인 후 수행한다.
- PDF·이미지의 '내 질문 포함'은 파일 출력 옵션이며 계정 저장 동의와 혼동하지 않는다. 계정 저장 버튼에는 질문·카드·해설이 계정에 저장됨을 명확히 표시한다.
- 로그아웃·다른 계정 로그인·상담 종료 시 메모리의 이전 사용자 기록과 생성한 파일 URL을 제거하여 계정 간 정보가 섞이지 않게 한다.
- 일반 회원에게 super 권한을 부여할 때 기존 저장 기록이 있으면 자동 삭제하지 않는다. 운영자가 사용자 동의하에 삭제를 완료한 뒤 전환하여 '저장하지 않는다' 안내와 모순되지 않게 한다.
- 서비스 로그, 분석 이벤트, 오류 보고에 질문·해설 원문을 기록하지 않는다. Gemini에는 해설 생성에 필요한 내용이 전송되며 공급자 자체 보관 정책까지 '절대 저장 없음'으로 약속하지 않는다. 일반 회원 기록은 서버 보관이므로 개발자도 기술적으로 열람 불가능한 암호화라는 약속을 하지 않는다.

## 슈퍼 첫 로그인 안내

제목: SUPER ACCOUNT!!

본문: 작성하신 질문과 타로 해설은 별도로 저장하지 않아요. 안심하고 마음껏 무료로 즐겨주세요.

로그인 후 서버에서 super 역할과 미확인 상태를 확인한 경우만 팝업과 짧은 폭죽 효과를 표시한다. CSS 기반으로 구현하고 reduced-motion 환경에서는 정적인 장식으로 대체한다. '확인'을 누르면 확인 시각을 DB에 저장한다. 저장 성공 후에는 캐시를 삭제하거나 다시 로그인해도 재표시하지 않는다. 실패하면 안내를 유지하고 재시도 가능하게 한다. 실제 슈퍼 대상은 사용자가 지정한 가입 완료 계정만 사용하며 개발자가 추정해 임의 지정하지 않는다.

## 후속 결제·광고 경계

잔액 및 권한은 브라우저 값으로 결정하지 않는다. 결제 승인 검증, 광고 완료 검증, 중복 지급 방지, KST 일자별 3회/1장 제한, 해설 실패 시 시트 복구를 서버에서 처리한다. 상세 구현은 제공자와 상품 정책을 확정한 후 별도 설계한다. 1차에서 미구현 API에 성공 응답을 만들지 않는다.

## 검증과 배포

관련 검사만 수행한다: 타입/빌드, 로그인 취소·성공·재로그인, 본인 기록 접근, 다른 사용자 접근 차단, super 저장 차단 및 역할 변경 차단, 안내 확인 1회, 계정 전환 시 임시 기록 초기화, 모바일 280px 팝업. 유료 Gemini 호출이나 실제 결제는 검증을 위해 임의 실행하지 않는다. OAuth 사용자 동의는 본인이 완료한다.

현재 문서는 구현 전 검토본이다. 승인 뒤 짧은 실행 계획을 작성하고 검토받은 후 순차 구현한다. 외부 인증 설정·DB 변경·운영 배포는 아직 수행하지 않았다.
