# 타로타르트 모바일 PWA 첫 화면 개편 설계

## 목적

기존 타로타르트 리딩 서비스에 모바일 앱다운 브랜드 랜딩과 타로 유형 선택 화면을 추가한다. 기존 원 오라클 리딩 흐름은 유지하고, 아직 구현되지 않은 세 가지 유형은 명확한 준비 중 상태로 노출한다. 새 화면은 최소 280px 너비에서도 레이아웃과 텍스트가 겹치거나 잘리지 않아야 한다.

## 범위

### 포함

- `/` 브랜드 랜딩 화면 개편
- `/select` 타로 유형 선택 화면 추가
- 원 오라클에서 기존 `/shuffle` 흐름으로 이동
- 쓰리카드, 켈틱 크로스, 호로스코프의 준비 중 안내
- 모바일 반응형 및 접근성 보완
- 설치 가능한 PWA를 위한 매니페스트, 앱 아이콘, 서비스 워커, 오프라인 안내 보완
- Vercel 프로덕션 빌드 검증

### 제외

- 쓰리카드, 켈틱 크로스, 호로스코프 실제 리딩 기능
- 기존 원 오라클 해석 로직과 데이터 변경
- 회원가입, 로그인, 결제, 서버 데이터 모델 변경
- 데스크톱 전용 레이아웃

## 사용자 흐름

1. 사용자가 `/`에 접속한다.
2. 타르트와 타로 카드 일러스트, 서비스명 `타로타르트`, 소개 문구를 확인한다.
3. `시작하기`를 누르면 `/select`로 이동한다.
4. 사용자가 네 가지 유형 중 하나를 선택한다.
5. `원 오라클`을 선택하면 기존 `/shuffle`로 이동한다.
6. 다른 세 유형을 선택하면 현재 화면을 유지하며 `준비 중이에요` 안내를 확인한다.
7. 선택 화면의 뒤로가기 버튼 또는 브라우저 뒤로가기로 랜딩 화면에 돌아갈 수 있다.

## 화면 설계

### 브랜드 랜딩 `/`

- 상단: 영문 보조 브랜드 `TAROT TARTE`
- 중앙: 기존 `public/main.png` 일러스트, `타로타르트` 제목, 짧은 소개 문구
- 하단: 한 손으로 누르기 쉬운 전체 너비 `시작하기` 버튼
- 녹색 배경, 골드 포인트, 크림색 본문으로 기존 브랜드 자산과 일관성을 유지한다.
- 화면 높이가 짧아도 버튼이나 일러스트가 잘리지 않도록 세로 스크롤을 허용한다.

### 유형 선택 `/select`

- 상단: 뒤로가기 버튼, `어떤 타로를 볼까요?` 제목, 안내 문구
- 본문: 세로로 배치된 네 개의 유형 카드
  - 원 오라클 — 힌트 찾기
  - 쓰리카드 — 직관적인 답
  - 켈틱 크로스 — 마음 들여다보기
  - 호로스코프 — 내 전체 흐름
- 원 오라클에는 이동 가능 상태와 화살표를 표시한다.
- 나머지 유형에는 `준비 중` 배지를 표시하되 버튼으로서 선택과 안내가 가능하도록 한다.
- 준비 중 안내는 시각적으로 확인되고 스크린 리더에도 전달되는 짧은 상태 메시지로 제공한다.

## 컴포넌트와 데이터 경계

- `app/page.tsx`: 랜딩 화면 조합과 `/select` 이동만 담당한다.
- `app/select/page.tsx`: 유형 목록 렌더링, 뒤로가기, 유형 선택 동작을 담당한다.
- 유형 이름, 부제, 상태, 이동 경로는 `constants/tarotTypes.ts`의 정적 설정 배열로 관리한다.
- 유형 카드 컴포넌트는 표시와 클릭 이벤트 전달만 담당하며 라우팅 규칙을 내장하지 않는다.
- 기존 `MenuButton`은 새 화면 요구와 책임이 다르므로 억지로 확장하지 않고, 새 유형 카드로 대체한다. 사용되지 않게 되면 제거 여부를 구현 시 참조 검색으로 판단한다.
- 기존 Zustand 타로 유형 스토어에는 원 오라클 선택값 `one`을 계속 저장해 후속 흐름과 호환한다.

## 반응형 및 접근성

- 지원 너비: 최소 280px부터 일반 모바일 너비 430px 이상까지.
- 고정된 600px 너비와 화면 중앙 강제 변환을 제거하고 `width: 100%`, 제한된 `max-width`, `min-height: 100dvh`를 사용한다.
- 간격과 제목 크기는 `clamp()`로 축소 가능하게 만든다.
- 모든 주요 버튼의 터치 영역은 최소 44px 높이를 확보한다.
- `env(safe-area-inset-*)`를 사용해 노치와 홈 인디케이터 영역을 피한다.
- 의미 있는 버튼 요소, 대체 텍스트, 키보드 포커스 표시를 제공한다.
- `prefers-reduced-motion`에서는 장식 애니메이션과 페이지 전환을 최소화한다.

## PWA 설계

- 매니페스트의 이름, 색상, 시작 경로와 표시 방식을 브랜드에 맞게 보완한다.
- 192px 및 512px 앱 아이콘을 제공하고 적절한 목적 값을 선언한다.
- 클라이언트 등록 컴포넌트에서 동일 출처 서비스 워커를 등록한다.
- 서비스 워커는 `/`, `/select`, `/offline.html`, 브랜드 이미지와 앱 아이콘을 설치 시 캐시한다. 문서 탐색은 네트워크를 먼저 사용하고 실패하면 캐시된 경로 또는 `/offline.html`을 반환한다. 이미지와 폰트는 캐시를 먼저 사용한다.
- 배포 갱신 시 캐시 이름을 버전 관리하고 오래된 캐시를 정리한다.
- Supabase API 응답과 사용자 선택 결과는 오프라인 캐시에 영구 저장하지 않는다.

## 오류 및 상태 처리

- 준비 중 유형을 눌러도 잘못된 경로로 이동하지 않는다.
- 서비스 워커 등록 실패는 앱 사용을 막지 않으며 개발 환경 콘솔에서만 진단 가능하게 한다.
- 오프라인 상태에서 아직 캐시되지 않은 리딩 경로를 요청하면 오프라인 안내 화면을 보여준다.
- `main.png`에는 의미 있는 대체 텍스트를 제공하고 이미지 로딩 중에도 레이아웃 높이를 유지한다.

## 검증

- TypeScript 검사와 Next.js 프로덕션 빌드를 통과해야 한다.
- `/`, `/select`, `/shuffle` 주요 경로를 직접 확인한다.
- 280px, 320px, 375px, 430px 뷰포트에서 가로 스크롤, 겹침, 잘림이 없어야 한다.
- 시작하기, 뒤로가기, 원 오라클 이동, 준비 중 안내를 키보드와 터치로 확인한다.
- 매니페스트, 서비스 워커 등록, 오프라인 폴백, 앱 아이콘 요청을 확인한다.
- 기존 원 오라클 카드 섞기와 결과 흐름이 변경 전과 동일하게 동작하는지 회귀 확인한다.

## 배포

- 환경 변수나 데이터베이스 변경은 요구하지 않는다.
- Vercel에서는 기존 Next.js 프로젝트 설정을 그대로 사용한다.
- 프로덕션 빌드가 통과한 뒤 Vercel 미리보기에서 설치 가능성, 모바일 safe area, 오프라인 안내를 최종 확인한다.
