# 쓰리카드 리딩 설계

## 목표

사용자가 다섯 가지 쓰리카드 배열 중 하나를 직접 선택하고, 고민 주제에 맞춰 세 장을 뽑은 뒤 세 장을 연결한 결론과 각 자리의 해석을 좌우 페이지 방식으로 확인한다.

## 사용자 흐름

1. 타로 방식 선택에서 `쓰리카드`를 선택한다.
2. 쓰리카드 배열 하나를 선택한다.
3. 고민 주제 하나를 선택한다.
4. 질문을 생각하며 셔플 애니메이션을 본다.
5. 배열의 첫 번째 자리부터 세 장을 차례대로 선택한다.
6. 좌우로 넘기는 네 페이지의 결과를 확인한다.

원오라클은 기존 `타로 방식 → 주제 → 셔플 → 한 장 선택 → 결과` 흐름을 유지한다.

## 쓰리카드 배열

| 배열 | 첫 번째 | 두 번째 | 세 번째 |
| --- | --- | --- | --- |
| 시간의 흐름 | 과거 | 현재 | 미래 |
| 문제 해결 | 상황 | 장애물 | 조언 |
| 관계의 흐름 | 나 | 상대 | 관계 |
| 선택의 갈림길 | 선택 A | 선택 B | 결정의 열쇠 |
| 답의 방향 | NO | 보류 | YES |

`답의 방향`은 카드 세 장의 단순 다수결이 아니다. NO는 진행을 막는 신호, 보류는 더 확인할 변수, YES는 가능성을 여는 조건으로 읽고, 종합 결과는 현재 어느 방향에 가까운지와 방향을 바꿀 조건을 함께 설명한다.

## 화면 구성

### 배열 선택

- 쓰리카드에서만 주제 화면 전에 표시한다.
- 다섯 개 배열을 단일 선택 카드로 보여준다.
- 선택 표시가 분명해야 하며, 배열을 선택하기 전에는 하단 이동 버튼을 표시하지 않는다.
- 280px 너비에서도 가로 넘침이나 문구 겹침이 없어야 한다.

### 카드 선택

- 기존 셔플과 숫자 카드 선택 동작을 재사용한다.
- 세 개의 선택 슬롯과 선택된 실제 카드 아래에 배열의 자리 이름을 계속 표시한다.
- 선택 순서는 첫 번째, 두 번째, 세 번째 자리로 고정한다.
- 선택된 카드가 세 장 모두 뒤집힌 뒤 결과 화면으로 이동한다.

### 결과

- 세로로 긴 해석 목록 대신 가로 스와이프가 가능한 네 페이지로 구성한다.
- 1페이지: 세 장을 연결한 짧은 결론, 흐름 요약, 마지막 행동 조언.
- 2~4페이지: 해당 자리명, 카드 이미지와 이름, 자리 관점에 맞춘 세부 해석.
- 하단에 이전·다음 버튼과 페이지 점 표시를 제공한다.
- 마지막 페이지에서는 홈으로 돌아가는 동작을 제공한다.
- 스와이프와 버튼 이동이 같은 현재 페이지 상태를 사용한다.

## 해석 데이터와 조합

- 기존 `tarot_card_profiles`, `tarot_base_interpretations`, `tarot_topic_readings` 데이터를 기본 재료로 사용한다.
- 새로 18,720개 해석 행을 저장하지 않는다.
- 배열 정의와 자리별 관점 문구는 코드의 고정 설정으로 관리한다.
- 쓰리카드 API는 카드 ID 세 개, 고민 주제, 배열 ID를 받아 필요한 카드 및 주제 해석을 한 번에 조회한다.
- 조합기는 각 카드의 기존 결론·핵심 흐름·감정·과제·기회·미래·조언 중 자리와 가까운 내용을 선택하고 자리별 설명을 덧붙인다.
- 종합 결론은 세 카드의 핵심 키워드와 자리 사이의 연결을 이용해 `결론 → 흐름 → 행동 조언` 순서로 구성한다.
- 실시간 AI 호출은 사용하지 않아 응답 지연, 비용, 결과 편차를 만들지 않는다.

## 상태와 이동 보호

- 선택한 쓰리카드 배열을 별도 Zustand 상태로 보관한다.
- 쓰리카드인데 배열이 없으면 배열 선택 화면으로 돌려보낸다.
- 타입이나 주제가 없으면 기존 흐름 보호 규칙에 따라 앞 단계로 돌려보낸다.
- 홈으로 돌아가거나 새 리딩을 시작하면 카드, 주제, 배열 상태를 함께 초기화한다.

## 오류 처리

- 카드 한 장의 상세 해석이 없으면 카드 프로필의 한 줄 해석과 키워드로 해당 페이지만 대체한다.
- 일부 카드 조회 실패 때문에 전체 결과 화면을 막지 않는다.
- 요청 자체가 잘못됐거나 카드 세 장을 확보하지 못했을 때만 이전 단계로 돌아갈 수 있는 오류 화면을 보여준다.

## 검증과 배포

- 배열 선택과 다음 단계 이동을 확인한다.
- 다섯 배열의 자리 순서와 세 카드 선택 순서가 일치하는지 확인한다.
- 결과 네 페이지의 순서와 좌우 이동 경계를 확인한다.
- 기존 원오라클 흐름이 유지되는지 관련 테스트로 확인한다.
- 타입 검사와 프로덕션 빌드를 실행한다.
- `master`에 커밋·푸시한 뒤 Vercel 프로덕션 배포가 Ready인지 확인하고 실제 API 응답을 점검한다.
