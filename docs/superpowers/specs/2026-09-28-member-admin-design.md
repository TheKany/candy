# 회원 관리와 슈퍼 안내 확인

## 합의한 범위

관리자 목록에는 회원번호, 가입일, 등급, 상태, 상세 버튼만 표시한다. 닉네임, 이메일, 질문, 카드, 해설은 관리자 응답과 화면에서 제외한다. 상세 화면은 결제 이력만 제공한다. 잔액 수정, 회원 삭제, 이용 제한 기능은 이번 범위에서 제외한다.

## 화면과 접근

- `/admin/members`: 회원번호 검색, 페이지 단위 목록, 일반/슈퍼 등급 변경.
- `/admin/members/[memberNumber]`: 결제 일시, 상품, 금액, 결제/취소/환불 상태. 결제 연동 전에는 실제 결제 내역이 없음을 표시한다. 샘플 결제나 광고 보상을 결제로 표시하지 않는다.
- 관리자만 마이페이지에서 진입 버튼을 볼 수 있다. 직접 URL/API를 호출해도 동일한 서버 권한 검증을 거친다.
- 관리자는 일반/슈퍼 등급과 별도 권한이다. 지정된 사용자 UUID만 별도 관리자 테이블에 등록하며, 브라우저에서 관리자 권한을 부여할 수 없다. 실제 최초 관리자 UUID는 적용 전에 본인 확인을 받는다.

## 회원 식별과 상태

- 기존 auth UUID는 내부 연관 키로 유지한다. 별도 난수 회원번호를 DB에서 생성하고 UNIQUE 제약과 충돌 재시도로 중복을 막는다. 기존 회원도 채우고 회원번호는 변경하지 않는다.
- 상태의 이용 기준은 완료된 타로 상담이다. 가입 후 완료 내역이 없으면 미사용, 내역이 있고 마지막 완료 후 90일 미만이면 사용중, 90일 이상이면 휴면으로 계산한다.
- 휴면은 목록 표시일 뿐 로그인이나 무료 혜택을 차단하지 않는다. 별도 배치 작업 없이 조회 시 계산한다.
- 기존 member_activity의 완료 시각만 사용하며 질문·키워드·해설을 관리자용 조회에 포함하지 않는다.

## 등급 변경과 확인 기록

- 일반/슈퍼만 수정 가능하다. 대상 회원번호와 변경 등급을 확인한 뒤 저장한다.
- DB 트랜잭션에서 등급 변경과 관리자 변경 이력을 함께 기록한다. 실제 등급이 달라질 때만 기록하고 확인 상태를 초기화한다. 같은 슈퍼 등급으로 다시 저장하는 것은 초기화하지 않는다.
- 기존 `super_notice_ack_at`와 본인 전용 `acknowledge_super_notice` RPC를 재사용한다. 확인 기록은 DB에 보관하며 브라우저 캐시를 사용하지 않는다.
- 마이페이지 진입 시 계정 정보를 새로 확인한다. 슈퍼이며 확인 시각이 없으면 팝업을 연다. 다른 페이지에는 표시하지 않는다.
- “확인했어요” 클릭 후 DB 저장 성공 시 닫힌다. 실패 시 안내를 유지하고 재시도를 제공한다. 계정 정보 재조회에도 실패하면 성공했다고 표시하지 않는다.
- 일반으로 변경됐다 다시 슈퍼가 되면 새 안내를 표시한다. 이전 안내에 대한 오래된 확인 요청이 새 승격 안내를 확인 처리하지 않도록 등급 변경 버전을 함께 검증한다.

## 보안과 결제 경계

- 서버의 로그인 검증과 DB의 관리자 검증을 함께 적용한다. 슈퍼 등급만으로 관리자 조회를 허용하지 않는다.
- 제한된 관리자 RPC만 회원 목록/등급 변경을 제공한다. 기존 본인 전용 RLS를 전체 회원 읽기로 확장하지 않는다.
- 변경 요청은 동일 출처 검증, 입력 검증, DB 권한 검증을 거친다. 관리자 비밀 키를 브라우저에 제공하지 않는다.
- 결제 서비스 및 결제 원장 구현은 현재 없다. 이번에는 빈 결제 상세 상태까지 구현하고, 실 결제 연동 시 서버에서 검증된 결제 원장을 연결한다. 관리자 화면에서 결제를 생성하거나 환불하지 않는다.

## 제한된 검증

비관리자 접근 차단, 등급 변경/확인 초기화, DB 확인 유지, 상태의 90일 경계만 집중 검증한다. 목록과 마이페이지 팝업을 확인하고 타입 검사를 실행한다. 관련 없는 전체 테스트나 결제 모의 구현은 하지 않는다.

## 적용 순서

설계 승인 → 짧은 구현 계획 → 로컬 코드 및 DB 마이그레이션 작성 → 제한된 검증 → 최초 관리자 UUID 확인 및 DB 권한 적용. 배포는 별도 요청 시 진행한다. 기존 미배포 변경과 사용자 데이터는 보존한다.
