# 켈틱 크로스 리딩 설계

## 목표

사용자가 고민 주제를 정하고 열 장의 카드를 직접 선택한 뒤, 정·역방향과 켈틱 크로스의 자리 관계를 반영한 입체적인 결과를 모바일 페이지 방식으로 확인한다. 기존 원오라클과 쓰리카드 흐름 및 해석 데이터는 그대로 유지한다.

## 사용자 흐름

1. 타로 방식 선택에서 `켈틱 크로스`를 선택한다.
2. 기존 고민 주제 중 하나를 선택한다.
3. 질문을 생각하며 기존 셔플 애니메이션을 본다.
4. 안내되는 자리 순서에 따라 카드 열 장을 숫자로 직접 선택한다.
5. 선택이 끝나면 카드별 정·역방향을 공개하고 결과 화면으로 이동한다.
6. 하단 이전·다음 버튼으로 전체 배치, 카드별 해석 열 개, 종합 결론을 확인한다.

켈틱 크로스에는 별도의 배열 선택 단계를 추가하지 않는다. 기존 주제 키워드와 셔플 경험을 재사용한다.

## 열 개 자리

| 순서 | 자리 | 해석 관점 |
| --- | --- | --- |
| 1 | 현재 상황 | 질문의 중심과 지금 작동하는 핵심 에너지 |
| 2 | 장애물 | 현재 상황을 가로막거나 밀어붙이는 영향 |
| 3 | 내면의 원인 | 무의식, 뿌리, 아직 명확히 드러나지 않은 원인 |
| 4 | 의식적인 바람 | 사용자가 알고 있는 목표, 기대, 지향점 |
| 5 | 지나간 영향 | 지금은 약해지고 있지만 현재에 남은 과거의 영향 |
| 6 | 다가오는 흐름 | 가까운 시기에 들어오는 변화와 전개 |
| 7 | 나의 태도 | 상황을 대하는 사용자의 자세와 선택 방식 |
| 8 | 주변 환경 | 상대방, 관계, 외부 조건과 주변의 반응 |
| 9 | 희망과 두려움 | 기대와 불안이 동시에 만드는 심리적 긴장 |
| 10 | 최종 흐름 | 현재 선택이 이어질 때 도달할 가능성이 높은 방향 |

전통적인 중앙 1~6번과 오른쪽 기둥 7~10번 구조를 사용한다. 1·2번, 3·4번, 5·6번, 7~10번을 각각 하나의 해석 묶음으로도 읽는다.

## 정방향과 역방향

- 열 장 각각에 정방향 또는 역방향을 무작위로 한 번만 배정한다.
- 배정된 방향은 결과 화면을 벗어나기 전까지 바뀌지 않도록 카드 선택 상태와 함께 보관한다.
- 역방향 카드는 선택 공개 및 카드별 결과 페이지에서 이미지를 180도 회전하고 `역방향` 문구를 함께 표시한다.
- 전체 배치도의 2번 카드는 전통적인 교차 형태로 가로 배치하되, 별도 방향 표기로 정·역방향을 구분한다.
- API는 카드별 방향 배열을 받아 같은 방향의 `tarot_topic_readings` 데이터를 조회한다.

## 카드 선택 화면

- 기존 셔플, 1~78 위치 안내, 숫자 키패드, 카드 가져오기 연출을 재사용한다.
- 상단에는 `열 장 중 N번째 카드`와 현재 자리 이름을 표시한다.
- 이미 선택한 카드는 작은 켈틱 크로스 슬롯에 순서대로 채워 현재 진행 상황을 보여준다.
- 열 장을 한 번에 나열하지 않고, 중앙 6장과 오른쪽 기둥 4장의 관계가 보이는 축소 배치도를 사용한다.
- 중복 번호는 선택할 수 없고, 잘못된 번호에는 기존 입력 오류 안내를 사용한다.
- 열 번째 카드 공개가 끝난 뒤에만 결과 페이지로 이동한다.
- 280px 너비에서도 숫자 키패드, 자리 안내, 선택 카드가 겹치거나 가로로 넘치지 않아야 한다.

## 결과 화면

결과는 총 12페이지이며, 화면 터치나 스와이프가 아니라 하단 이동 버튼으로만 전환한다.

1. 전체 배치: 중앙 십자 6장과 오른쪽 기둥 4장, 카드 번호, 정·역방향, 자리 범례.
2. 2~11페이지: 선택 순서대로 자리명, 카드명, 정·역방향, 한 줄 결론, 주제별 세부 해석, 해당 자리를 돌아보는 질문.
3. 종합 결론: 짧은 결론을 맨 앞에 두고 핵심 갈등, 내면, 시간 흐름, 주변과 결과의 연결, 마지막 행동 조언 순으로 표시한다.

하단에는 이전·다음 버튼과 현재 위치 점 표시를 둔다. 점 표시는 클릭할 수 없다. 마지막 페이지의 다음 버튼은 홈으로 동작한다. 각 페이지 내부 내용이 작은 화면 높이를 넘을 때만 해당 페이지 안에서 세로 스크롤을 허용한다.

## 해석 데이터와 조합

- 기존 `tarot_card_profiles`, `tarot_base_interpretations`, `tarot_topic_readings` 세 테이블만 사용하며 새 해석 테이블이나 대량 데이터를 만들지 않는다.
- 켈틱 크로스 API는 카드 ID 열 개, 방향 열 개, 고민 주제를 검증한 뒤 필요한 프로필과 방향별 주제 해석을 한 번에 조회한다.
- 카드별 페이지는 저장된 결론·요약·감정·과제·기회·미래·조언 중 자리의 관점과 가까운 필드를 우선 사용하고, 자리 설명과 성찰 질문을 덧붙인다.
- 종합 조합기는 다음 순서로 결과를 만든다.
  - 1·2번: 현재 핵심과 충돌
  - 3·4번: 무의식의 원인과 의식적인 목표 사이의 간극
  - 5·6번: 지나가는 영향과 다가오는 변화
  - 7~9번: 나의 태도, 주변 환경, 희망과 두려움
  - 10번: 현재 흐름이 이어질 때의 가능성
- 같은 키워드의 반복을 줄이고, 각 카드의 핵심 키워드를 연결 문장의 근거로 사용한다.
- 결과는 단정적인 예언이 아니라 현재 흐름과 선택 가능한 행동을 설명한다.
- 실시간 AI 호출은 사용하지 않아 응답 속도, 비용, 문체를 일정하게 유지한다.

## 상태와 이동 보호

- 켈틱 크로스는 선택 카드 열 장과 카드별 방향 열 개가 모두 있어야 결과 요청을 보낼 수 있다.
- 타로 유형이나 주제가 없으면 기존 이동 보호 규칙에 따라 앞 단계로 돌려보낸다.
- 카드 또는 방향이 열 개가 아니거나 중복 카드가 있으면 결과 요청을 거부하고 카드 선택으로 돌아갈 수 있게 한다.
- 홈으로 돌아가거나 새 리딩을 시작하면 카드, 방향, 주제 상태를 초기화한다.
- 결과 페이지 도달 시 기존 완료 리딩 방문자 집계 방식을 그대로 사용한다.

## 오류 처리

- 특정 카드의 주제별 방향 해석이 없으면 해당 카드의 기본 해석과 키워드로 그 카드 페이지만 대체한다.
- 일부 해석이 대체되어도 나머지 카드와 종합 결과는 표시한다.
- 카드 프로필 자체를 확보하지 못하거나 요청 형식이 잘못된 경우에만 전체 오류 화면과 카드 선택 복귀 버튼을 표시한다.

## 검증과 배포

- 켈틱 크로스 선택 시 주제 화면으로 이동하고 기존 미지원 표시가 사라지는지 확인한다.
- 열 개 자리 순서, 중복 방지, 정·역방향 보존, 열 장 선택 후 결과 이동을 관련 테스트로 확인한다.
- 조합기가 자리별 관점과 네 개 해석 묶음을 올바른 순서로 반환하는지 확인한다.
- 12페이지 버튼 이동 경계와 마지막 홈 이동을 확인한다.
- 기존 원오라클과 쓰리카드의 핵심 테스트가 유지되는지 확인한다.
- 280px 화면을 한 번 점검하고 타입 검사와 프로덕션 빌드를 실행한다.
- `master`에 커밋·푸시한 뒤 Vercel 프로덕션 배포와 켈틱 크로스 API 응답을 확인한다.

## 제외 범위

- 공유 이미지 또는 PDF 생성
